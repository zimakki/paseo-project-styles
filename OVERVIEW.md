Makes projects and workspaces easy to tell apart in the sidebar. Project names are bigger and bold. Each project's workspaces are indented and smaller, with a coloured rail on their left. The rail takes the colour of the project's letter avatar. A project with an image icon gets a colour picked from its name, so the colour stays the same between sessions.

Each workspace row also shows its agent status across the whole row, in the pinned section too. The row takes the colour of whatever needs you most: an amber wash when an agent needs input, red when one failed, green when one finished and you have not opened the workspace yet, and a light band sweeping across the row while an agent is working. Finished ranks above working, so a finished agent still shows when another agent in the same workspace is busy. When something more urgent owns the row and an agent is also working, a thin blue line sweeps along the bottom edge instead. A sub-agent that another agent started and that has since closed never turns its row green or red. Paseo gives it no tab and keeps it marked unread, so the row would otherwise stay coloured with nothing to open.

Background tasks (a background shell, a monitor, a heartbeat) never count as an agent working. While one runs, a terminal icon with a blinking cursor replaces the row's status dot, in the row's colour, with a count when there are several. Paseo's blue spinner is hidden, because the sweep already says an agent is working. A collapsed project row gets the same treatment for all its hidden workspaces together. With reduced motion turned on, the sweep and the bottom line hold still and the cursor stops blinking.

The workspace you have open gets a thin ring in its project's colour and a bold name, so you can find it whatever its agent status. A pinned workspace has no project colour in the sidebar, so its ring is grey.

The plugin adds a stylesheet to the app and targets the sidebar's test IDs. Paseo does not offer a plugin API for the sidebar, so a Paseo release that renames those IDs stops the styling until the plugin is updated. Nothing breaks when that happens; the sidebar just looks like the default again.

It works in the desktop and web apps. The mobile app has no stylesheet to change, so it shows the default sidebar. The styling only applies when the sidebar is grouped by project. To work out each row's state, the plugin reads the agent list of each host the sidebar shows, through Paseo's own client API. Until that list has loaded, rows show Paseo's own status. The plugin has no settings, reads nothing outside the app, and sends nothing anywhere.
